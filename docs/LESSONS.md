# LESSONS.md — Lessons learned as a review checklist (project-independent)

> Every rule originated from a **real, found bug** — the reference in brackets
> points to the backlog archive of the origin project (evidence, not prerequisite).
>
> **Usage:** before every review, before every phase completion and when creating new
> routes/endpoints/caches, work through this checklist. Goal: never make the same mistake twice.

## A. Security & tenant separation

1. **Parameterized values do not protect the keys.** Dynamic SQL (SET/ORDER-BY over object keys) needs a **column whitelist**. *(Evidence: K1)*
   - Check: every repo update that interpolates body keys into SQL → whitelist or 400.
2. **Every `:id` route checks ownership, not only the role.** Pattern: load object → compare owner → otherwise 403/404. Applies to sub-resources too. *(K2)*
   - Check: test matrix "foreign tenant → 403/404" for every `:id` route including sub-resources.
3. **Protection by registration order is not protection.** A route that is only secure because another handler was registered earlier is a latent gap — guard at the resource itself, prove independence with a test. *(H2)*
4. **Secrets fail hard, not with a warning.** In production with default secrets/passwords: process abort with a clear message; `${VAR:?…}` instead of `:-default` in compose. *(K4)*
5. **Public auth endpoints get throttled.** Login, recovery, anonymous creation: simple rate limits — otherwise large keyspaces and partial hashes are no time problem for attackers. *(H3)*
21. **Format validation is not authorization.** An ID that passes `isValidUuid` can still belong to another tenant — format checks and ownership checks are different gates. Every **new reference type** in request bodies (e.g. a `media_id` column added by a migration) adopts the full established template at introduction: whitelist → format → ownership → evil-case test. *(M71)*
22. **Business rules enforced only in the UI are suggestions.** Any gate/restriction the product promises (release gates, limits, slug locks, immutability) is reachable via the API by definition — enforce it server-side; the UI only mirrors it. Check: for every frontend-only rule, find the endpoint that bypasses it. *(M72)*
23. **Payload projections are whitelists, not omit-lists.** `Omit<Row, …>` + `...rest` forwards every future schema column automatically — each migration re-opens the leak until the list is updated by hand. Build public payloads from explicit field lists and guard the field set with a contract test. *(M73/99.2 — same leak class twice)*
24. **Count-then-write limits race.** Quota checks that count first and insert in a second statement can be exceeded under concurrency. Serialize on a row lock (`SELECT … FOR UPDATE` on the limit anchor) or document the accepted best-effort explicitly. *(L47)*

## B. Tests that find something

6. **Tests must not mirror their own implementation.** "Smooth" fixtures confirm the code instead of checking it. Always include **realistic/evil** variants: mixed spellings, foreign keys, giant payloads, foreign tenant IDs. *(K3, K1, K2 — simple tests would have found all three)*
7. **Secure contracts at the test seam, from both sides.** Where two layers share the same convention (code case, lengths, payload fields), there must be a test on **both** sides with a **shared** fixture source — otherwise one side "guesses" the other. *(K3, T3)*
8. **In-memory clients (inject/mocks) hide host and environment logic.** IP/host-based resolution looks correct in the integration test and breaks in real HTTP — always test host logic with real requests. *(Phase-4 finding: 127.0.0.1 as "subdomain")*
9. **Silent catches are diagnostic poison.** `catch(() => {})` without logging turns errors into "mysteriously does not work". Minimum: a warn log with context. *(SW registration finding)*

## C. Frontend & browser reality

10. **URL-keyed caches must not store personalized responses.** If a response contains user-specific data, a service worker must not cache it under the bare URL — extend the key with the session or split the response. *(H1)*
11. **The router does not remount on param change.** `useRef(searchParams.get(…))` freezes the first value — keep refs in sync or set remount component boundaries. *(M2)*
12. **Plan for device reality.** iOS needs `requestPermission()` inside a user gesture; headless browsers sometimes do not know service workers. Always build device features with a permission flow + fallback; E2E with a suitable browser channel. *(M4, E2E experience)*
13. **Environment-dependent values (build IDs, paths) must be deterministic OR fail hard.** Silent fallbacks ("package version") lead to old bugs that never surface. Pattern: allow an env override, but indeterminacy = build error. *(M5, phase-5 finding)*
29. **Affordances must act — a button that does nothing is either superfluous or a bug.** Every visible control needs evidence that it *does* something: test the **effect** (state change, rendered DOM, print root), never the call or the mere existence — a `print()` caller without a print root and a primary button without a handler both rode through green suites. Dead controls are deleted or fixed, never parked; when a whole class can be caught mechanically, build the scanner. *(Evidence: Impeccable review 03.10.2026 — P0 "Wirkungsbericht druckt leere Seite", P1 dead upload primary button; mechanical guard → T34)*

## D. Build & process

14. **Bundler `define` values are expressions, not values.** `JSON.stringify` exactly once for strings/arrays — double stringify produces strings instead of arrays and fails silently at runtime. *(SW `addAll(String)` finding)*
15. **Security self-review before "done".** Deliberately walk through your own attack surface: "What can a *different* tenant do? An unauthenticated one? An admin with an evil body?" — the regular test suite mostly checks happy paths. *(R1 protocol)*
16. **Mechanical mass replacements with placeholders are dangerous.** Replace only with exact, unique strings; placeholders must never collide with real content; always run a diff/anomaly check afterwards. *(Evidence: archival slip 09/2026 — a `.Replace('X', …)` destroyed every "X" in three files)*
17. **Structure operations belong to the tool.** Status maintenance in the progress table, detail-block, Done-Index and archive changes always run through the tools built for it (`progress_update`, `archive_item`) — manual edits to these structures create exactly the drift the tools are meant to prevent. Only the prose that the tool deliberately does not manage (goal/acceptance texts, item content, new BACKLOG items) is edited directly in the files. *(Evidence: method-docs 09/2026 — status edits by hand in PROGRESS.md despite available tools, uncovered at the next validate.)*
18. **Measure exit codes in the host language.** PowerShell `$LASTEXITCODE`, POSIX `$?`/`$status` — never cmd `%ERRORLEVEL%` expansion after `&` (expanded at parse time, shows the value from before the run); inside cmd itself only with `!ERRORLEVEL!` under `/v:on`. *(Evidence: R9 — method-docs 09/2026, false alarm 🔴 → measurement artefact)*
19. **Sidecars that depend on the schema must tolerate "not yet migrated".** A `restart: unless-stopped` job next to the DB starts in parallel and can run **before** migrations on a fresh volume — the table is then missing and the run aborts into its next-interval pause. Either `depends_on` a migration gate, or classify "table does not exist" (PG `42P01`) explicitly as *too early* (skip, exit 0) and retry on the next run; never let it look like a permanent failure. *(Evidence: R6 beta deploy — `analytics-cleanup` crashed with `42P01` before `dbSetup` had run)*
20. **Reverse-proxy config: `add_header` is not inherited, and some proxies inject their own.** In nginx, if the *inner* level (`location`) has any `add_header`, all outer `add_header` are silently dropped (even with `always`). With NPM/OpenResty the built-in `proxy.conf` adds `X-Served-By` inside `location /`, so custom security headers set in the UI's "Advanced" tab never reach real responses — use the bundled **headers-more** module (`more_set_headers`) instead. Verify on the **actual** response (including an error status), not on the 301. *(Evidence: R6 beta deploy — HSTS/nosniff/Referrer-Policy were absent on the 502/200 while present on the HTTP redirect)*
25. **Transitions need termination items.** A dual state (new path + legacy fallback) is only acceptable with a backlog item that removes the fallback — otherwise transition architecture becomes permanent architecture and every read path carries both code paths forever. *(M74/L53)*
26. **Prose rules decay — mechanical guards don't.** A structural convention that matters (size limits, layering, naming) gets a mechanical check (structure test/lint) at the moment it is defined; a rule not worth a guard is a recommendation, not a rule. *(L46 — the 400-line rule lived only in AGENTS prose)*
27. **An artifact nobody boots is unverified — and a contract test must cover its caller.** If a build step transforms output for a runtime entry point (`node dist/`, container CMD), the pipeline must import/boot that exact artifact at least once (smoke in build/CI); a green build only proves compilation, not startability. And when shared rewrite/emit logic is contract-tested, test the **call site** against the same contract — the walker passed the wrong path shape while the tested function was correct. *(K6 — Dist-Rewriter produced `dist/dist/…` paths for four phases because E2E ran alias-natively via tsx and CI built the image without starting it.)*
28. **CI is a verification lane, not a notification board — its view is part of "verified".** The local machine is one OS/scheduler with lucky timing: concurrency code (parallel writes, row locks) and pipeline-only steps (`docker run` in Actions, workflow plumbing) are only exercised where CI actually runs — and CI can only gate what it has seen. Push **at every phase boundary at the latest** (push interval ≤ phase); a red run must point at the introducing phase, not at a pile of dozens of commits.
   - Check: before archiving a phase, its commits are pushed and the CI run for them is green; never let unpushed work accumulate past one phase. *(Evidence: F7 — the M95 empty-tour lock hole survived two days and several local green runs, then failed on the first Ubuntu CI run; the verify:dist `docker run` step got its first CI execution eight phases after introduction because 104 commits sat unpushed.)*
30. **Identifiers a human types are compared in exactly one normalized form.** If the login trims/lowercases an e-mail but the create path stores the raw input, the account becomes unreachable (401 forever), resets silently find nothing, and a case-sensitive `UNIQUE` admits duplicate identities that differ only in spelling. Normalize **on write** and compare on the **same canonical form**; where the database is the last line (uniqueness), index the normalized expression, not the raw column. *(Evidence: code review 26.10.2026 — `POST /api/admin/users` stored `Max@Example.de`, login compared `max@example.de`; tenant/region creation and `setup:admin` normalized correctly, so the drift sat in exactly one new path.)*
31. **A test owns its artifacts and its end state — never the shared source tree.** A file a test writes only for a subprocess (probe for a lint/config guard) belongs **outside** every directory other tests scan: parallel workers list a directory and read it afterwards, so a probe that appears and vanishes inside `src/` becomes `ENOENT` in an unrelated guard under load. And a test must **await the state it caused** (fetch flush, `act`) instead of ending on an in-flight update — React then reports `not wrapped in act` on stderr. Both defects pass single-file runs and only surface in the full lane, so a clean isolated run is no evidence. *(Evidence: M197 — probe file in `src/frontend/shared/` raced `contentHeaderFieldsGuard` in the coverage lane; T48 — the skeleton test released its fetch and ended, 4 act warnings per run.)*
