### Scope-model decision (user-initiated during this retro)

User observation: lessons mix universals with project-class-specific ones, and
more dimensions exist (languages, application stack, project type) — the file
does not model the distinction. Decision:

- **Section-level scope tags with a small closed vocabulary** — `*(scope: web/API)*`,
  `*(scope: frontend)*`, untagged = universal. Four tags, not 31 per-lesson
  decisions; the sections already cluster by domain, and the named dimensions
  (language/stack) correlate strongly with the two tagged domains.
- Tags are **hints for the reviewer, not gates** — the review checklist stays a
  judgment aid; a rich multi-dimensional scope matrix is deliberately rejected
  as over-engineering for a 31-entry checklist (Lesson 26 spirit: mechanical
  form, minimal weight).
- New vocabulary values only when a lesson actually needs one.

## Topology limitation (documented, not built)

The cross-repo sync contract (verbatim copies + SHA256 evidence) is a
**same-machine agent ritual** — verified again this retro (manual
`sha256sum` + file edit in the sibling copy). Foreign-machine copies receive
the files at adoption and drift until someone visits them. Accepted cost:

- Revisit only if a cross-machine copy actually materializes in the method's
  use. A sync tool for method docs is rejected for now: it would be
  M4-questionable surface AND would break the "tools never edit method docs"
  boundary (PLAYBOOK/LESSONS edits are deliberate, evidenced human/agent
  contracts).
