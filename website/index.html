The Reality of AI Coding

The "Agent Drift" Crisis

LLMs don't fail because they can't write code. They fail on multi-turn tasks because free-hand document editing leads to silent drift, hallucinated completion, and prompt bloat.

✕

Without Stepwell

  • •
    Corrupted Documentation: The agent manually modifies Markdown tables, destroys pipes, forgets headers, or deletes previous context.
  • •
    Token Waste: Agent re-reads entire 2,000-line progress files on every session turn, burning 30,000+ context tokens unnecessarily.
  • •
    Hallucinated Progress: Checked-off items linger in open lists; completed steps have no verifiable commit SHA audit trail.
  • •
    Scope Creep: Agent takes on 4 tasks at once without approval gates, breaking tests in unrelated directories.
✔

With Stepwell

  • •
    Deterministic Tool Mutations: The agent never touches table formatting directly. Mutates only through verified tools (`progress_update`, `archive_item`).
  • •
    Radical Token Economy: `docs_status` with `nextStepScope` gives the exact target in 1 call (~400 tokens). SHA-256 hash skip saves redundant reads.
  • •
    Dry-Run First & Audit Trails: Every write yields a line-diff preview. Completed phases require commit SHAs; items move verbatim to append-only archives.
  • •
    Strict Human & Content Gates: Audited RED-first test requirements. CI fails automatically with exit code 1 if documentation drifts.

Structure & Schema

        
The 4-File Architecture

        

          Stepwell standardizes project management into four deterministic Markdown files. Clean separation between active work and append-only archives.
        

      


      

        
        

          

            BACKLOG.md
            Active
          

          

            Priority-sorted open items (🔴 Critical → 🔵 Test gaps). Contains only items currently pending implementation.
          

          

            ### [ ] H1 — Build-Pipeline fix *(🟠 High)*

            - **Location:** packages/mcp

            - **Acceptance:** npx stepwell runs without build step
          

        


        
        

          

            PROGRESS.md
            Active
          

          

            Progress table (`⬜ 🔄 ✅ ⛔`) and detailed goal, scope & acceptance blocks for currently active phases.
          

          

            | Step | Task | Status |

            | 18.1 | Multi-step progress update | ✅ |

            | 18.2 | Locale surface polish | ✅ |
          

        


        
        

          

            docs/archive/BACKLOG_ARCHIVE.md
            Append-Only
          

          

            Completed backlog items moved verbatim with `[x]` checkbox, completion timestamp, and commit SHA reference.
          

          

            ### [x] H1 — Build-Pipeline fix

            - **Completed:** Commit cb10583 (260910/1820)
          

        


        
        

          

            docs/archive/PROGRESS_ARCHIVE.md
            Append-Only
          

          

            Full phase detail blocks migrated upon phase completion (`progress_update`), retaining permanent auditability.
