The agent drift problem

LLMs don't fail because they can't write code. They fail on multi-turn tasks because free-hand document editing leads to silent drift, hallucinated completion, and prompt bloat.

Without stepwell

  • Corrupted documentation. The agent manually modifies Markdown tables, destroys pipes, forgets headers, or deletes previous context.
  • Token waste. Agent re-reads entire 2,000-line progress files on every session turn, burning 30,000+ context tokens unnecessarily.
  • Hallucinated progress. Checked-off items linger in open lists; completed steps have no verifiable commit SHA audit trail.
  • Scope creep. Agent takes on 4 tasks at once without approval gates, breaking tests in unrelated directories.

With stepwell

  • Deterministic tool mutations. The agent never touches table formatting directly. 14 tools cover reads, mutations, and repairs; every write dry-run first.
  • Radical token economy. docs_status with nextStepScope gives the exact target in 1 call. SHA-256 hashes short-circuit redundant reads.
  • Dry-run first & audit trails. Every write yields a line-diff preview and is re-parsed and verified after apply. Archives stay append-only: verbatim, never rewritten.
  • Strict human & content gates. Audited RED-first test requirements, per-file-class content gates. CI fails with exit code 1 if documentation drifts.

Four working principles

          
Stepwell is designed around constraints that guarantee safety, zero lock-in, and fast agent turns.

        

        

          

            

              
              Dry-run first
            

            
All write operations generate exact line diffs first (dryRun: true by default). Writes happen only with explicit --apply, and the result is freshly re-parsed and verified before success is reported.

          

          

            

              
              Token economy
            

            
nextStepScope merges step, goal, and backlog item into a single call. SHA-256 hash short-circuits prevent redundant document reads; compact JSON and field projection keep every payload lean.

          

          

            

              
              Zero-dependency core
            

            
Markdown is the only source of truth. The core engine has 0 runtime dependencies, runs natively in Node.js 22+ (type stripping, no build step), and keeps all history append-only in Git, git-blind by design.

          

          

            

              
              Auditable governance
            

            
Content-risk matrix (low, medium, high) gates every file class. Test-first (RED → GREEN) enforcement, coverage gate, and checkpoint SHAs; phases move into the archive only verified.

          

        

      

    


    
    

      

        

          
Four core files, sharded by phase

          
Four mandatory Markdown files; every project starts with exactly these. The default archive write,
          though, is sharded by phase: while a phase runs, completed history appends to per-phase shard files,
          never to the canonical archives. Rotation is a tool operation, never a hand edit.

        


        

          

            

              BACKLOG.md
              mandatory · active
            

            
Priority-sorted open items (🔴 critical → 🔵 test gaps), one item = one block with
            Location/Acceptance bullets. > No open items. placeholders
            keep empty sections honest, and docs_validate flags lying markers.

            
### [ ] H9 — Mechanical repair path *(🟢 Low)*
- **Location:** packages/core/src/validate.ts
- **Acceptance:** RED→GRÜN, docs_validate clean

          


          

            

              PROGRESS.md
              mandatory · active
            

            
The permanent step index (⬜ 🔄 ✅ ⛔) plus detail blocks with goal, scope & acceptance —
            only for currently active phases.

            
| Step | Task                          | Status |
| 32.5 | PLAN_WITHOUT_WIP fix          | ✅     |
| 33.1 | Field test round 1            | 🔄     |

          


          

            

              docs/archive/BACKLOG_ARCHIVE.md
              append-only
            

            
Completed items move verbatim with [x] and a done line. While phase n runs —
            the normal case, the block and its Done-Index line land in the phase shard
            BACKLOG_ARCHIVE.p<n>.md, created with a greppable header line. The canonical file
            only receives appends made outside a running phase and holds the legacy stock.

            
### [x] H9 — Mechanical repair path *(🟢 Low)*
- **Done:** Commit 4b6c2a1
# shard: docs/archive/BACKLOG_ARCHIVE.p33.md

          


          

            

              docs/archive/PROGRESS_ARCHIVE.md
              append-only
            

            
On phase completion the detail block moves verbatim into its own shard
            PROGRESS_ARCHIVE.p<n>.md (header line included). Appends stay
            chronological by completion time; phase numbers across shards may stay non-monotonic (M10).
            The progress table remains the permanent index.

            
### Phase 33 — Field Test (Completed: 2026-11-12T21:30)
**Verification:** Checkpoint 4b6c2a1 (suite green)

          

        

      

    


    
    

      

        

          
Parallel phases without merge hell

          
One phase per git worktree + branch, merged back to trunk per step. The core engine stays
          git-blind: all git intelligence lives in the stepwell-git satellite, offered
          CLI-first (no MCP registration needed) and MCP-optional (workstream_sync).

        


        

          

            
            per-step workstream ritual
          

          

            

              
$ stepwell sync pull --root <worktree> # trunk → branch, conflicts abort cleanly

              
# … implement test-first, verify (typecheck + tests) …

              
$ stepwell progress-update … --apply --commit # doc commit: ONLY the doc files

              
$ stepwell sync push --root <worktree> # branch → trunk, atomic --ff-only

              
$ stepwell sync status --root <worktree> # liveness + overlap of all workstreams

            

          

        


        

          

            

              
              Foresight before edits
            

            
predictedOverlap[] lists files that open items on both sides name in their Location bullets —
            visible before anyone edits them. idCollisions[] catches both sides reaching for the same next item ID.

          

          

            

              
              Guarded operations
            

            
Stable error codes: DIRTY_TREE, STALE_BRANCH, TRUNK_DIRTY,
            MERGE_CONFLICT (clean abort with a structured report). Dry-runs share the exact guard chain of the
            real operation; push is atomic --ff-only.

          

          

            

              
              Doc-commits only
            

            
commit: true stages only the doc files (+ archive shards): deterministic staging,
            no secret risk. Code commits stay with the agent; a failed doc commit never rolls back the edits.
